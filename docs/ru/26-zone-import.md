# 26. Перенос зон со старого мастера

Задача не «импорт файлов», а **переезд**: на старом BIND сотни зон, и их надо забрать вместе с записями,
ничего не набивая руками. Сценарий один: старый BIND → эта панель.

## Откуда берётся список

Спросить у DNS «перечисли свои зоны» нельзя: AXFR работает только по известному имени, а каталога
(RFC 9432) у старого сервера нет. Список приходит файлом, который BIND раскладывает сам:

```
named-checkconf -p > bind-export.conf
```

`include` уже раскрыты, всё приведено к одному виду. Файл разбирается один раз и ложится списком в БД
(`import_sources` + `import_zones`); сам файл не хранится (только его sha256). В колонки идёт то, по чему
фильтруют и решают: имя, роль, `masters` у slave-зон, признак динамической, признак подписи; остальное
прочитанное (ACL, `also-notify`, `allow-query`, forwarders, имена ключей, zone-файл, незнакомые директивы) —
в `config_json`, для глаз. Из ключей и ACL панель берёт только то, что нужно динамическим зонам: кто вправе
их обновлять, вместе с секретами этих ключей (в браузер секреты не уходят).

Адрес старого DNS берётся из файла (`listen-on`, непетлевые адреса): кандидат один — подставляется;
несколько — панель их называет и ждёт выбора.

## Как переезжает содержимое

Записи забирает **сам PowerDNS по AXFR**, а не парсер:

```
зона заводится как Secondary → AXFR → видно, что приехало (SOA, число записей)
   → дальше это обычная зона панели: Make primary или пусть стоит Secondary
```

Приезжает ровно то, что старый сервер **сейчас отдаёт**.

### Откуда зона будет приезжать

| чем была на старом сервере | откуда берём мы | что дальше |
|---------------------------|-----------------|------------|
| `master` / `primary` — зона его | у **него** | зеркало с маркером переезда `X-DNSPANEL-IMPORT`; повышаем, когда готовы |
| `slave` / `secondary` — зона чужая | у **её собственных мастеров** (`masters` из конфига) | обычная secondary-зона панели, без маркера; повышать незачем |

Подставить всем адрес сервера экспорта нельзя: чужая зона обновлялась бы ровно до его выключения, а потом
тихо застыла бы.

## Каждая загрузка — отдельная операция

Одна загрузка — **один старый DNS**. Второй сервер грузится когда угодно потом; его список сравнивают с тем,
что в панели есть СЕЙЧАС:

| Что в панели | Что показываем |
|--------------|----------------|
| зоны нет | `new` — завести Secondary с этого источника |
| Secondary с ЭТОГО же адреса | `same source` — уже взята отсюда |
| Secondary с другого адреса | `other source` — уже есть, взята с другого адреса |
| Primary/Native | `ours` — уже есть, наша |

**Существующую зону импорт не трогает никогда.** Что делать с совпадением, решает человек в Compare (ниже).
Две версии одной зоны не смешиваются. Чем зона была на другом старом сервере, база не помнит: `other source`
говорит только «Secondary от такого-то адреса», рядом — роль из нынешнего экспорта.

Повторная загрузка экспорта **того же** мастера обновляет строки по имени, добавляет новые, изменившиеся
видит по `config_hash`, а исчезнувшие помечает `gone` (`last_seen_at` старше загрузки). Признаки `new` и
`changed` сбрасываются в начале каждой загрузки этого источника — фильтр `Since last load`.

Состояние строки:

| состояние | что значит |
|-----------|------------|
| `pending` | ещё ничего не делали |
| `imported` | завела ЭТА операция переноса (`panel_zone_id` наш, зона на месте) |
| `imported_gone` | мы её заводили, но зоны в панели уже нет |
| `exists` | **конфликт**: зона с таким именем есть, но пришла не отсюда («Conflict — already exists») |
| `reviewed` | выбрана текущая версия («Kept current») |
| `failed` | попытка была и не вышла, причина в `note` |

## Разбор: что помечается

- **Динамические зоны** (`allow-update`, `update-policy`). `allow-update` раскрывается через именованные ACL в
  адреса и ключи; `update-policy`, `any`, отрицания и прочее, что перенести нельзя, показываются как есть.
  Признак пишется зоне (`X-DNSPANEL-IMPORT-DYNAMIC`) в той же транзакции, что и сама зона.
- **Подписанные зоны** (`auto-dnssec`/`inline-signing`) — `X-DNSPANEL-IMPORT-DNSSEC`, см. «DNSSEC» ниже.
- **`in-view "…";` — не зона**, а ссылка на ту же из другого view; такие блоки зонами не считаются.
- **Одно имя с несколькими настоящими определениями** (split-horizon) — `review`, выбрать нельзя: у панели зона
  на имя одна.
- **Пустой `forwarders { };`** ничего не значит; непустой — `review`.
- **Корневая зона `.` (`hint`)** в список не попадает. Прочие неподдерживаемые типы (forward, stub…) видны, но
  без галочки.
- **Незнакомые директивы** не выбрасываются: их имена попадают в `review`, и зона помечается флажком.

## Экран

**Settings → Import.** Сверху — те же фильтры, что на Zones (общий компонент): поиск, Status, Kind, Type,
Dynamic, Master, DNSSEC, Review, Since last load и `Clear`, который появляется, только когда что-то выбрано.
Выбор строк — галочкой в шапке, как в Users & access: берёт видимые после фильтра строки, скрытые фильтром из
выбора не теряются. **Галочки сами не проставляются.** Щелчок по имени раскрывает строку: всё прочитанное из
конфига и всё, что панель знает о своей зоне с тем же именем.

### Probe source

Колонки `Source serial` и `Source records` — **сторона старого сервера и только она**. Опрашивается сервер
импорта (`import_sources.master`), и у его slave-зон тоже. Один AXFR через dns-agent (`axfr_at`) даёт serial и
число записей. **Probe source** только ставит зоны в очередь (`probe_state = queued`); опрашивает worker —
пачкой за проход (`settings.import.probe_batch`, по умолчанию 50; не дольше `import.probe_budget_seconds`,
60 с), результат лежит в строке (`source_serial`, `source_record_count`, `probed_at`). Не отдал — бейдж
`no transfer` с причиной: REFUSED — не пускает allow-transfer, SERVFAIL — у него самого зона не загружена,
NOTAUTH — зона не его или не принят ключ. Не ответил вовсе — причина сразу у всех зон источника в очереди.
Не опрашивали — прочерк. У зоны, которая есть и у нас, при другом serial — бейдж `serial differs`.

### Compare и Copy

**Compare** (в раскрытии строки, у зоны, которая есть в панели) — живой AXFR с источника против нашей зоны в
PowerDNS (`GET /import/zones/:id/diff`). Две таблицы рядом: слева **Import · адрес источника**, справа
**Current**, у каждой serial. Одна строка — одно имя+тип, в порядке зоны; отличия подсвечены, разный TTL
подписан. Переключатель `All changes` (по умолчанию) / `Different` / `Import only` / `Current only` /
`Identical` с числами и поиск по имени меняют только видимость строк. SOA сравнивается целиком, кроме serial.
Обе стороны нормализуются одинаково (имена, в том числе внутри CNAME/NS/PTR/MX/SRV/SOA, — нижний регистр без
точки; приоритет MX/SRV в данных); данные подписи (RRSIG/NSEC/DNSKEY…) не сравниваются.

**Copy — отдельные записи, без импорта зоны.** Стрелка → переносит RRset из Import в Current целиком
(имя+тип). Пока это только окно: справа появляется версия Import, × отменяет перенос; галочки (у Import only) +
`Copy N selected` — сразу несколько, выбор переживает смену фильтра и поиск. В зону пишет только `Apply
changes`: `POST /import/zones/:id/copy {rrsets:[{name,type}]}`. Браузер шлёт только ключи — содержимое сервер
берёт из живого AXFR. Путь записи — тот же, что у правки записей (`pdns_apply_rrsets`: одна транзакция, один
bump serial, аудит `replace_rrset` с пометкой «copied from import»), права — write на зону. Роль, профиль,
раздача не меняются; SOA и NS вершины не копируются; у Secondary стрелок нет.

У зоны в конфликте в том же окне — решение по зоне целиком:
- **Keep current** — строку больше не предлагаем (`reviewed`); передумать можно там же.
- **Import this version** (`POST /import/zones/:id/take`) — зона становится тем, чем её сделал бы перенос:
  Secondary оттуда же (у master-зоны источника — он сам, у его slave-зоны — её мастера), с теми же пометками.
  Primary проходит через Make secondary (записи стираются, каталог снимается, подтверждение именем зоны);
  у Secondary меняется только источник и сразу запрашивается AXFR.

## TSIG

**Ключ для AXFR с сервера экспорта** — один общий контрол, тот же, что у любой Secondary-зоны (Add zone, Zone
settings → Upstream primaries, Make secondary): None / существующий ключ / «+ Add key…» (имя, алгоритм,
секрет; можно вставить BIND-блок `key {…}`). Какой ключ старый сервер требует, из его конфига не следует,
поэтому контрол появляется, только когда Probe показал отказ в передаче (REFUSED/NOTAUTH или отвергнутый
ключ) или ключ уже выбран. Зона хранит только имя ключа (`AXFR-MASTER-TSIG`).

- Новый ключ заводится один раз на пачку, в панели и в PowerDNS, после всех общих проверок. Имя, уже занятое
  ключом в PowerDNS, — отказ: чужой секрет панель не переписывает.
- После каждой пачки новый ключ проходит уборку: если на него никто не ссылается (например, в пачке были
  только чужие secondary-зоны), он удаляется. Уборка смотрит настоящие ссылки и используемый ключ не трогает.
- **Probe и Compare подписываются тем же ключом**, что выбран для переноса; имя запоминается у источника
  (`import_sources.probe_tsig`), секрет worker берёт из PowerDNS. Ключ в режиме «новый» опросу недоступен —
  его заводит первый перенос. dns-agent отдаёт ключ dig через stdin и считает ошибкой запуск, в котором dig
  не прочитал ключ (иначе dig молча делает AXFR без подписи).
- **Чужие secondary старого сервера** едут со своих мастеров со своим ключом: ключ с тем же именем уже есть в
  PowerDNS — ставится сам, иначе в строке пометка `TSIG key required: <name>`, и ключ задают в Zone settings.
- Ключ, которым после `Make primary` или удаления зоны никто не ходит, уходит из панели и из PowerDNS сам.

## Заведение — общим путём

`POST /zones/import` несёт только `source_id` и имена; зоны создаются той же функцией, что и «Add zone»
(`pdns_create_zone`). Всё остальное ядро берёт **из сохранённого списка**, а не из браузера:

| из списка | зачем |
|-----------|-------|
| `import_sources.master` | адрес сервера экспорта |
| `import_zones.source_type` | его зона или чужая, переносится ли AXFR'ом вообще |
| `import_zones.source_master` | настоящие мастера чужой secondary |
| `last_seen_at` | зоны нет в последней загрузке — отказ |
| `dynamic`, DNSSEC, `allow-update` | пометки зоны и её настройки Dynamic updates |

Браузер шлёт пачки по 50 (ядро принимает до 200). Зона, которая не завелась, приходит **внутри успешного
ответа** пачки, и перенос продолжается; отказ самого запроса перенос останавливает, экран перечитывает список,
повтор безопасен. Зона и её маркеры — одна транзакция; строка `import_zones` — следом, и если она не
записалась, зона снимается и идёт в неудачи. Заведённые зоны PowerDNS узнаёт одним `rediscover` на пачку,
дальше по каждой — запрос AXFR; приезд наблюдает worker. Агент не ответил — остальным зонам пачки сразу
`transfer_problem`.

Профиля при переносе нет: SOA и NS приезжают по AXFR, а один профиль на пачку врал бы — в одном экспорте зоны
разных брендов. `X-DNSPANEL-PROFILE` не пишется, `Make primary` SOA и NS не переписывает; профиль при желании
ставят в Zone settings.

**Динамические зоны** получают настройки «кто вправе» сразу при импорте (у secondary они ждут Make primary):
есть Dynamic DHCP profile с одним из старых ключей — зона ему следует; иначе адреса и ключ из `allow-update`
(ACL раскрыты). Ключ берётся из самого экспорта (`key { algorithm; secret; }`) и заводится один раз на все
зоны; ключ панели с тем же именем и другим секретом не трогается — у зоны пометка. Ключ в файле не определён
(include не попал в экспорт) — пометка `TSIG key required`, а форма Dynamic updates подставляет имя и
алгоритм и просит только секрет. Зона, у которой настройки уже были, их сохраняет. Перенаправить DHCP на наш
адрес — конфиг DHCP-сервера, панель им не управляет.

В журнале — запись `create_zone` на каждую зону и отдельная `import_zones` про пачку.

## Повышение — отдельный шаг, у самой зоны

Импорт делает зону **зеркалом старого сервера**: Secondary без раздачи вниз. Повышают там же, где любую
другую зону: **Zone settings → Make primary**. Что при этом проверяется и происходит:

- **повышается только приехавшее**: зона без SOA — отказ;
- **версия сверяется с источником**: у зоны с `X-DNSPANEL-IMPORT` Make primary спрашивает SOA у старого
  сервера (`soa_at` через dns-agent) и сравнивает serial. Fail-closed: не ответил или разошлись — не
  повышаем. Обойти можно только явно (`ignore_source_serial`) — когда старый сервер уже выключен;
- **динамические** (`X-DNSPANEL-IMPORT-DYNAMIC`) — только с приёмом обновлений и только когда настройки
  заданы: в окне Make primary приём включается сам, иначе смена роли молча отрезала бы DHCP;
- **подписанные** — с переносом своих ключей или явно без DNSSEC (ниже);
- маркеры переноса снимаются; раздача не меняется — прямой AXFR и каталог назначают в Zone settings.

### DNSSEC

Подписанная зона приезжает зеркалом с чужими подписями. Ключи загружаются из бейджа **DNSSEC** в строке
импорта: модалка по живому набору DNSKEY источника называет нужные файлы `K<zone>.+<alg>+<tag>.key/.private`
и принимает их (`POST /import/zones/:id/dnssec/keys`); приватные части хранятся в строке списка до повышения.
Там же — выбор «Drop DNSSEC» (`PUT /import/zones/:id/dnssec`): зона повышается неподписанной, DS у регистратора
надо снять заранее.

`Make primary` переносит ключи (`_dnssec_promote_plan` / `_dnssec_promote_finish`):

1. каждый DNSKEY, пришедший по AXFR, должен совпасть целиком (флаги, алгоритм, открытый ключ) с загруженной
   парой, иначе отказ `DNSSEC private key missing`;
2. ключи заводятся через API ещё у secondary и читаются обратно — PowerDNS должен держать те же DNSKEY, иначе
   откат;
3. смена роли; снимаются presigned-данные (RRSIG/NSEC/NSEC3/DNSKEY/CDS/CDNSKEY/TYPE65534) и флаг `PRESIGNED`,
   NSEC3PARAM остаётся прежним, новый serial и rectify;
4. приватные ключи из списка импорта удаляются.

DS у регистратора не меняется.

### Постепенная замена живого мастера (cutover)

Если старый BIND — действующий primary с кучей своих secondary, повышение — **момент смены владельца зоны**.
Порядок для одной зоны:

```
1. зона импортирована, стоит Secondary у старого BIND                → прод не тронут
2. старый BIND заведён в Propagation и зоне включён Direct AXFR — ДО повышения
3. заморозили изменения на старом BIND
4. Make primary в панели (сам сверяет serial со старым BIND)
5. сразу следом на старом BIND зона становится Secondary нашего PowerDNS
       PDNS Primary → старый BIND Secondary → его secondary как ходили, так и ходят
6. по одному переводим secondary на нашу раздачу; последний ушёл — старый BIND выключается
```

**Сначала повышаем себя, потом понижаем старый сервер**: наоборот получилась бы петля из двух Secondary, и
сверять serial было бы не с чем. Короткий промежуток, когда primary двое, безопасен: изменения заморожены,
версии сверены.

**Шаг 2 обязателен**: импортированная зона заводится без раздачи, и старый сервер получил бы REFUSED. Нужны оба
условия: старый сервер в Propagation (его адрес попадает в `ALLOW-AXFR-FROM`) **и** Direct AXFR у зоны. Если он
в группе с TSIG — ему нужен ключ. Конфиг старого BIND правится руками: им панель не управляет.
