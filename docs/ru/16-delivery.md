# 16 — Раздача зон: прямая раздача и каталоги

## Модель

У зоны **два независимых факта**. Ни один не выводится из другого, и правка одного не трогает второй.

| | Direct = None | Direct = Allow |
|---|---|---|
| **Catalog = нет** | никто | все разрешённые в Servers |
| **Catalog = A** | подписчики A | объединение |

- **Прямая раздача** — строка в `zone_direct_axfr`. Получатели не выбираются: это весь инвентарь Servers,
  где узлу разрешено брать зоны (личный `axfr_policy=allow` либо группа с `zone_axfr=1`).
- **Каталог** — `pdns.domains.catalog`, у самого PowerDNS. **Копии в панели нет намеренно:** две копии
  одного факта расходятся. Зону по каталогу берут только те подписчики, кому разрешено брать зоны; остальные
  получают от нас лишь список имён.
- **Сети группы** (`secondary_group_prefixes`, поле **Networks** у группы с выключенным Require TSIG) добавляются в
  `ALLOW-AXFR-FROM` зон, которые получает группа, рядом с адресами её серверов: для AXFR-клиентов, которые — сеть, а не
  сервер. TSIG-группа их не добавляет: PowerDNS объединяет ACL и TSIG через «или», и сеть разрешила бы передачу без
  подписи. NOTIFY сетям не уходит.

Каталог — самостоятельный объект: `catalogs(id, name, fqdn, pdns_domain_id, last_error)` плюс подписчики
(`catalog_groups`, `catalog_nodes`) и адреса нашего PowerDNS, которые каталог публикует
(`catalog_primary_endpoints`). Создаётся одним действием: строка плюс producer-зона (RFC 9432) в PowerDNS.
Плана, гейтов и отдельного шага apply нет.

Ограничение PowerDNS: PRODUCER объявляет только свои primary-зоны. Secondary в каталог **не берётся** —
отказ выдаётся явно. Раздавать её напрямую при этом можно (панель ставит ей `SLAVE-RENOTIFY`).

## Как это применяется

Единственная точка — `apply_zones(\@ids)` (или `undef` = все раздаваемые). Одна зона, список и фоновый
проход идут через неё.

Внутри: общее считается **один раз на вызов** (получатели прямой раздачи, подписчики затронутых каталогов,
NOTIFY-адреса узлов, сверка ключей с PowerDNS, текущие метаданные всех зон), на зону остаётся сравнение и
запись **различий**. Совпало — не пишем: каждая запись метаданных — вызов API.

Права зоны — `ALLOW-AXFR-FROM` + `TSIG-ALLOW-AXFR` + `ALSO-NOTIFY` — пишутся **одной операцией из одного
расчёта**: два пути, пишущие их порознь, затирали бы друг друга.

`X-DNSPANEL-POLICY` — метка панели: по ней восстановительный проход (`orphan_policy_sweep`) отличает нашу
политику от выставленной руками и снимает её с зон, которые больше никто не получает. Ставится первой при
применении и снимается последней при очистке.

## Что где живёт

| Вопрос | Источник истины |
|---|---|
| Зона в прямой раздаче? | `dns_panel.zone_direct_axfr` |
| Зона в каталоге? | `pdns.domains.catalog` |
| Кому отдаём зоны? | `secondary_groups.zone_axfr` + `secondary_nodes.axfr_policy` |
| Кто подписан на каталог? | `catalog_groups` + `catalog_nodes` |
| Дошёл ли каталог до сервера? | `catalog_subscriptions` (наблюдение по DNS, панель BIND не настраивает) |

## Два канала NOTIFY

Каталог уходит **всем** подписчикам, умеющим RFC 9432: по нему сервер узнаёт, что заводить, даже если
данные берёт не у нас. Сами зоны — только тем, кому мы их отдаём. `notify_policy=off` у сервера выключает
NOTIFY по зонам, но не по каталогу.

`send-signed-notify=no` на этой установке — намеренно: PowerDNS подписывает NOTIFY одним ключом на зону, и
остальные подписчики получали бы BADKEY.

## Проверка

Автотестов нет ([04-panel-code.md](04-panel-code.md#как-проверять)): раздачу проверяют на живой паре — `dig` к secondary,
`pdns_control`, журнал панели.
