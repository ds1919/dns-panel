# 02 — MariaDB and the panel database

A node has three databases: `dns_panel` (the panel: users, permissions, sessions, audit, distribution…), `pdns`
(the PowerDNS gmysql backend, [03-powerdns.md](03-powerdns.md)) and the local `dns_ha` (HA, not replicated —
[../02-ha-pair.md §3](../02-ha-pair.md#3-local-db-dns_ha)). Everything below is done by `deploy/install.sh`.

## Configuration: a standalone node ready for a pair

`etc/mariadb/dns-panel.cnf` is installed RIGHT AWAY, already on a standalone installation:

`deploy/install.sh` creates it from `dns-panel.example.cnf` with a RANDOM server_id and installs it as a symlink at
`/etc/mysql/mariadb.conf.d/60-dns-panel.cnf`. Check:
```bash
mysql -e "SELECT @@server_id, @@log_bin, @@gtid_strict_mode\G"
```

Re-running the script leaves an existing file untouched: its `server_id` may already be in the binlog and in
replication. `server_id` must differ between replication participants and is not dynamic in MariaDB.

The file enables the binlog (`log_bin` in the data directory, `binlog_format = ROW`), GTID (`gtid_strict_mode`),
`log_slave_updates`, `bind-address = 0.0.0.0` (the replica connects to the source over TCP) and excludes `dns_ha`
from replication. None of this is dynamic, so it is set in advance: otherwise pairing two RUNNING servers would
start with editing `my.cnf` and restarting MariaDB under live DNS. There is no replication yet — the node is just
ready for it. Port 3306 should be firewalled down to the management network.

> `read_only` and `skip_slave_start` are NOT included here: a standalone node must stay operational after a
> reboot. They are the HA role's fail-safe: creating a pair places `etc/mariadb/ha-failsafe.cnf` as a symlink
> `/etc/mysql/mariadb.conf.d/61-dns-panel-ha.cnf`, without restarting MariaDB — the current `read_only` value
> is set by the agent according to the proven role.

## Databases and users

Passwords come from `etc/secrets/` (generated by the installer); a re-run brings the user's password in line with the file.
Everything is written bypassing the binlog (`sql_log_bin=0`), and on STANDBY (`read_only=1`) nothing is written at all.

| user | host | privileges | login |
|---|---|---|---|
| `dnspanel` | `127.0.0.1`, `localhost` | `ALL` on `dns_panel` | password `panel-db.password` |
| `pdns` | `127.0.0.1` | `ALL` on `pdns` | password `pdns-db.password` |
| `dns-ha` | `localhost` | `ALL` on `dns_ha`; `READ_ONLY ADMIN, SLAVE MONITOR` on `*.*` | unix_socket |

The panel and PowerDNS connect over TCP to `127.0.0.1`, so `'…'@'127.0.0.1'` is required: `'…'@'localhost'`
matches only socket connections.

> Do **not** give the panel user `SUPER` / `READ ONLY ADMIN`: otherwise writes succeed even with `read_only=1` on
> STANDBY.

## Schema

Schemas are loaded only into an EMPTY database: `docs/INSTALL/schema.sql` → `dns_panel`, the gmysql schema from the package → `pdns`.
`schema.sql` does not alter existing tables, and there are no migrations; a schema change on the stand is `DROP DATABASE dns_panel`
and a re-run of the installer ([../01-standalone.md §2](../01-standalone.md#2-what-the-installer-does)). The tables
are described in [../../03-database.md](../../03-database.md).

## Connection from the panel

`etc/panel.toml` — passwords are not in the config but in secret files:

```toml
[panel_db]
host          = "127.0.0.1"
name          = "dns_panel"
user          = "dnspanel"
password_file = "/opt/dns-panel/etc/secrets/panel-db.password"
```
